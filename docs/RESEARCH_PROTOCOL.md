# Coherence research protocol — 17 November 2026

This round focuses on learned weights and training, following the user's request. Original VV-GPT3 checkpoints are read-only. No downloaded pretrained weights or paid services. Public Shakespeare is the first controlled case; private chat text will not be sent to research/search services.

## Evidence and hypotheses

- [TinyStories](https://arxiv.org/html/2305.07759v1): task/data simplicity matters for coherent small-model output; loss alone does not measure grammar, plot consistency or context tracking. Its small-model results required substantial training, not a few hundred updates. This motivates separating data, training budget, architecture and generation quality.
- [LLaMA, section 2.2](https://arxiv.org/html/2302.13971v1): RMSNorm, SwiGLU and rotary positions are a useful architecture candidate. Its large-scale result is not evidence this bundle will improve a small VV-GPT run.
- [SwiGLU](https://arxiv.org/abs/2002.05202), [RMSNorm](https://arxiv.org/abs/1910.07467), [RoPE](https://arxiv.org/abs/2104.09864): implement a selectable revised block while keeping original checkpoint compatibility. Match feed-forward parameter budget approximately; report actual parameters and timing.
- [Unlikelihood training](https://arxiv.org/html/1908.04319v2): train against incorrect repetitions instead of only suppressing them at sampling time. Test a conservative token-level adaptation with a 32-token negative context, unique candidates, exclusion of the true target, coefficient 0.1. This is a bounded-context adaptation, not a full paper reproduction. Keep likelihood-only as the control.
- [Compute-optimal training](https://arxiv.org/abs/2203.15556): data/training budget must be considered alongside size. Do not treat its large-model scaling constants as a proven prescription for this corpus/Mac.

Use the historical first 90% of tokens for continued training, stripping artificial paragraph markers after partitioning. Split the historical validation tail in half for current validation and test. The original checkpoint was selected using the whole historical validation tail; clearly label this limitation rather than calling it a never-used test.
2. From the same original Shakespeare `_best.pt`, train two separate children: ordinary cross-entropy and cross-entropy + token unlikelihood (0.1), each up to 1,200 updates, batch 8, context 256, seed 42, peak LR 1e-4, dropout 0.1, evaluation every 100, patience 6. Select by validation likelihood only. Evaluate the final chosen checkpoint on the full reserved historical test half and an external Hamlet slice that is not used in training/selection. Do not change choices in response to test results.
3. Architecture ablation: classic versus revised Transformer (RMSNorm, parameter-matched SwiGLU, RoPE). Both scratch Micro, same compact vocabulary fitted only on the existing public 80% train split, context 128, batch 16, LR 3e-4, dropout 0.1, 1,500 updates, evaluation every 100, seeds 42 and 123. Select within each run by validation; only evaluate held-out test after selection. These are architecture-bundle comparisons, not isolated component causal claims.
4. Fixed generation prompts and matched sampling without penalties or phrase blocking. Six public Shakespeare-style prompts, seeds 42 and 123, 160 new tokens, temperature 0.8, top-k 50, top-p 0.9. Preserve all outputs. Report token/word repetition, malformed markers and obvious truncation; inspect grammar and topic/speaker continuity with explicit qualitative limitations. No automated semantic judge is claimed.

## Interpretation

Report continued-training improvement relative to the user's actual existing checkpoint separately from the scratch architecture comparison. Same steps are not necessarily same elapsed compute. Retain losing candidates. Do not describe lower likelihood loss or mechanically reduced repetition as proof of general intelligence. New architecture cannot directly load incompatible old weights; continuing existing models keeps their architecture and vocabulary.

## Clean-language experiment (defined after inspecting Shakespeare continuations)

The continued Shakespeare model lowered reserved-text loss but still produced broken grammar and inconsistent dialogue. This motivates a separate data/task experiment, not a claim that architecture alone solves coherence. Use author-published TinyStories V2 GPT-4 training text (CDLA-Sharing-1.0). Download only a bounded prefix containing 21,000 complete stories; exact-deduplicate records; reserve 20,000 for training, 500 validation, 500 test. Split at whole-story boundaries and explicitly insert EOS separators. Record revision, hashes, counts and license. No pretrained weights, private-text uploads or paid APIs.

Train one revised decoder from scratch: 6 layers, width 192, 6 heads, compact BPE up to 4,096, context 256, batch 16, seed 42, LR 5e-4, dropout 0.1, 5,000 steps, validation every 250, patience 12. Tokenizer learns only from training stories. This is a limited-domain language model and an exploratory data experiment; it does not establish that the same architecture/budget will improve general chat. Select the best checkpoint on validation, evaluate up to 100,000 characters from the held-out story set once afterwards. Compare eight fixed prompts at seeds 42 and 123 with the original own-model Shakespeare checkpoint only as a demonstration of changed task capability, not a controlled architecture or fair in-domain benchmark. Preserve all samples and inspect grammar, entity consistency and cause/effect. Do not claim broad assistant ability from simple-story results.

## Exploratory second story budget

After inspecting all 16 planned story continuations, sentence structure was more conventional but entity/goal tracking failed. Validation continued to improve at the first budget's endpoint. Test one fixed continuation from that best checkpoint: 5,000 further steps, same data/vocabulary/architecture/context, seed 42, batch 16, LR 3e-4, dropout 0 (reduced from 0.1), evaluation every 250, patience 12. The fresh optimizer and dropout change mean this is an exploratory continuation recipe, not an isolated training-length experiment. Retain the initial checkpoint and only replace it when validation improves.

Do not reuse the first test slice for the primary new comparison. After selection, score both the first and continued story models on characters 100,000–199,999 of the same reserved 500-story test partition, which were not used by the first evaluation. This slice was chosen after seeing the first results and is not a new independent dataset; disclose the adaptive study design. Keep all same 16 prompt/seed continuations for paired qualitative inspection. These prompts have now informed the decision to train further, so any improvement on them is exploratory rather than confirmation on unseen tasks. Stop after this declared budget and report the resulting limitations without additional tuning on these outputs.
