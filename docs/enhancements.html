The training-speed experiment

Same public Shakespeare text, Nano decoder, batch 8, context 128 and seed 42. A compact vocabulary reduces the work in the embedding and output layers.

Improvements grounded in the original code

Keep the actual best model

The original final-save path retained live tensors: later training could overwrite the supposed best weights. All three final files differ from their separate best checkpoints. The new worker immediately saves the real best weights and keeps a separate resumable state.

Resume with the training state intact

Current Torch rejected the original resume load, which could fall back to starting fresh. Restricted checkpoint loading, optimizer/RNG restoration and explicit errors now make resume dependable. The CPU regression reaches exactly the same weights after interruption.

Preserve the information in your data

Emoji, punctuation, Unicode and speaker labels survive preparation. Common WhatsApp AM/PM exports and multiline messages are handled. Raw decoded uploads stay beside prepared copies; compact tokenizers learn from the training split only.

Make learning visible

Training and validation curves use fixed batches with dropout disabled. A separate final test follows checkpoint selection. Hover values, training pace, elapsed time and a measurement table give the dark studio a practical purpose.

Read the samples, not just the repetition score

The same original Shakespeare best checkpoint was tested with three fixed public prompts, 200 generated tokens and matched seeds. The mild penalty produced mixed results. Hard phrase blocking produced zero repeated four-token phrases by construction, but broke recurring delimiters and speaker labels. It is therefore opt-in.

Better coherence is not yet demonstrated. Sampling controls cannot supply grammar, knowledge or conversational ability the model has not learned. Further quality work should use a fixed prompt set, more varied clean text, multiple seeds and a fresh held-out evaluation before claiming a better model.
